# タイムゾーン

TimeWeave でタイムゾーンが関わる場面は3つあります。混ざりやすいので、分けて
説明します。

| 場面 | どのタイムゾーンが使われるか |
| --- | --- |
| 自分の画面の時刻表示と、予定に入力した時刻 | ブラウザ（端末）のタイムゾーン |
| 終日の予定がどの日になるか | **設定したカレンダーのタイムゾーン** |
| 共有相手の画面 | 相手のブラウザのタイムゾーン |

**別の地域の時刻で予定を入れるときは、この端末の時刻に直して入力してください。** 予定ごとに
タイムゾーンを選ぶ機能はありません。たとえば日本の端末からニューヨークの午前9時（冬時間）の
会議を入れるなら、日本時間の 23:00 と入力します。保存されるのは「その瞬間」なので、
ニューヨークの端末で開けば 9:00 と表示されます。

## カレンダーのタイムゾーンは何を決めるのか

設定の「タイムゾーン」は、**終日の予定をどの暦日として扱うか**を決めます。

「10月13日の終日の予定」は、どのタイムゾーンの10月13日なのかが決まらないと、
瞬間として定まりません。この設定がその基準になります。

空欄にすると**未設定**に戻ります。空欄は「値が無い」のではなく、「未設定」という
状態です。

### 言語とは逆向きの決まり方です

ここは意図的に非対称になっています。

| | 誰のものか | 理由 |
| --- | --- | --- |
| タイムゾーン | **共有者**のもの | 終日の予定は共有者のカレンダーの1日を指します。相手側で決められると、相手が日付の境界を動かせてしまいます |
| 言語 | **見ている人**のもの | 相手に読めない言語の画面を渡さないため |

## タイムゾーンを変えると何が変わるか

日付の境界が動く変更のときだけ、確認画面が出ます。そこには3行が表示されます。

| 変わるもの |
| --- |
| 終日の予定は、このタイムゾーンの暦日として解釈されます |
| 匿名共有ページに表示される空き時間が変わることがあります |
| **時刻を指定した予定（開始・終了時刻のある予定）は変わりません** |

3行目が重要です。**時刻を指定した予定は動きません。** 「14時の会議」は14時のまま
です。動くのは終日の予定の解釈だけです。

## 未設定のままだと起きること

未設定でも通常の操作はできます。ただし、共有に影響します。

設定画面には次の注意が出ます。

![設定ダイアログ。タイムゾーンの入力欄が空で、終日の予定と時刻指定の空き時間が同じ期間に含まれる場合は匿名共有ページで空き時間を表示できないという注意が出ている](/content/images/ja/tz-unset-notice.png)

> タイムゾーンが未設定のため、終日の予定と時刻指定の空き時間が同じ期間に含まれる
> 場合、匿名共有ページでは空き時間を表示できません（安全のため非表示になります）。

### なぜ表示できないのか

終日の予定は「暦の1日」、時刻を指定した予定は「瞬間」です。この2つが同じ期間に
あるとき、どちらが先かを決めるには**暦日を瞬間に変換する基準**が必要です。
タイムゾーンが未設定だと、その基準がありません。

推測で計算して「空いている」と伝えてしまうより、空き時間を表示しない側を選んで
います。この場合、相手の画面は「空き時間を正確に判定できませんでした」になります。

**終日の予定と時刻を指定した予定を両方使い、空き時間を共有するなら、タイムゾーンを
設定してください。**

## 繰り返し予定のタイムゾーン

時刻を指定した繰り返し予定は、**それ自身のタイムゾーン**を持ちます。カレンダーの
設定とは別です。

「毎朝9時」は、どのタイムゾーンの9時かが決まらなければ繰り返しの意味が定まらない
ためです。保存時にブラウザからタイムゾーンを判定できない場合、この種類の予定は
保存できません。

繰り返しのタイムゾーンを変えると**すべての回が別の瞬間に移動します**。このため
変更は別の操作として用意されており、予定の名前を変えただけで書き換わることは
ありません。個別に変更した回がある繰り返し予定では変更できません。

詳しくは [繰り返し予定](/ja/docs/recurring-events) をご覧ください。

## 夏時間の切り替えと時刻の入力

予定の開始・終了に入力した時刻は、ブラウザ（端末）のタイムゾーンの時刻として
扱われます。そのタイムゾーンに夏時間がある場合、切り替えの日には次の時刻があります。

| 時刻 | 予定ダイアログでの扱い |
| --- | --- |
| 存在しない時刻（時計が進む間） | 保存できません。時刻を変更してください |
| 2回ある時刻（時計が戻る間） | 1回目か2回目を選んでから保存します。選んだ回は保存され、開き直しても変わりません |

日本には夏時間が無いため、日本の時刻で使っている場合はどちらも起きません。
操作の詳細は [予定の作成・編集](/ja/docs/managing-events) をご覧ください。

## 相手の画面での時刻表示

共有リンクを開いた相手には、**相手のブラウザのタイムゾーン**で時刻が表示されます。

つまり、同じ共有リンクを別の国の相手が開くと、**表示される時刻は違います**。
これは意図した動作です。相手にとって意味のある時刻で見えるほうが役に立ちます。

| | 共有者の画面 | 相手の画面 |
| --- | --- | --- |
| 時刻の表示 | 共有者のブラウザ | 相手のブラウザ |
| 終日の予定の日付の基準 | 設定したカレンダーのタイムゾーン | **同じ**（共有者の設定） |

終日の予定がどの日かは共有者の設定で決まり、相手側では動きません。

## 日付がずれて見えるときの確認

### 自分の画面で終日の予定の日付がずれている

1. 設定のタイムゾーンを確認します
2. ブラウザのタイムゾーンと違っていないか確認します
3. 違っている場合、終日の予定は**設定したほう**の暦日として扱われています

ブラウザのタイムゾーンで見た日付と、設定したタイムゾーンで見た日付が違う予定は、
ずれて見えます。どちらで扱いたいかを決めて、設定を合わせてください。

### 共有相手と時刻が合わない

時刻を指定した予定は、相手のブラウザのタイムゾーンで表示されています。ずれている
のではなく、**同じ瞬間を相手の時刻で表したもの**です。

確認するときは、お互いのタイムゾーンを明示して話すのが確実です。

### 終日の予定が相手の画面で前日・翌日に出る

終日の予定は共有者のカレンダーのタイムゾーンの暦日として扱われます。相手のタイム
ゾーンがそれと大きく違う場合、相手の時計では前日や翌日にまたがって見えることが
あります。

これは変換の誤りではなく、「共有者の10月13日」という区間を相手の時刻で表した結果
です。

### 使えないタイムゾーンと言われる

「このタイムゾーンは使用できません。ブラウザの日付と時刻の設定をご確認ください」
と表示された場合、ブラウザが報告したタイムゾーン名をサーバが扱えません。
ブラウザの日付と時刻の設定を確認してください。
