# Android 実機テストの手順（P8-mobile-1）

自宅 LAN 内の Android Chrome から、Windows PC で動かしている開発サーバーへつないで確認するための手順です。
**本番の Supabase には接続しません。** 使うのはこのリポジトリのモック（架空のデータ）だけです。

## 安全のための決まり

- **信頼できる自宅 LAN でだけ**使ってください。公共・職場・ホテルの Wi-Fi では使わないでください。
- 開発サーバーを LAN に公開するのは**テストの間だけ**です。終わったら必ず止めてください（各手順の最後）。
- 実在の予定・個人情報・本物の共有リンクを入力しないでください。モックのデータはすべて架空です。
- インターネットへ公開しないでください（ポート転送・外部トンネル・クラウドへの公開をしない）。
- PC の IP アドレス（例: `192.168.0.x`）は、その場で確認して使います。ソースや設定ファイルに書き込みません。

## モードの違い

| 起動方法 | 予定の保存先 | ログイン | 共有ボタン | 用途 |
| --- | --- | --- | --- | --- |
| `npm run dev`（`.env` / `.env.local`） | **本物の Supabase** | Google | あり | 実機テストには**使わない**（本番に接続するため） |
| `npx vite --mode mock`（`.env.mock`） | その端末の localStorage | なし（ローカルモード） | **なし**（仕様: ローカルモードに共有は無い） | 予定の作成・保存・再編集・メモ・スワイプ |
| `npm run shots:api` ＋ `npm run shots:app`（`.env.mockapi`） | モック API（PC の 127.0.0.1:54321） | 架空のセッション | あり | PC のブラウザでの確認・スクリーンショット。**スマホからは使えない**（スマホの `localhost` はスマホ自身） |
| `npm run shots:api` ＋ `npx vite --mode mockapi-lan` | モック API（Vite 経由で中継） | 架空のセッション（下記のページで） | あり | **スマホからの共有画面の確認** |

注意: モック API は予定の書き込みを保存しません（いつも同じ架空の予定を返します）。予定の作成→保存→再編集は
**手順 A（ローカルモード）**で、共有画面は**手順 B**で確認します。

### 実機で見つかった問題の原因（2026-10-20 の調査）

- **共有ボタンが無い**: スマホで開いていたのはローカルモードでした。ローカルモードでは共有は使えない仕様です（不具合ではありません）。
- **`crypto.randomUUID is not a function`**: `crypto.randomUUID` は**安全なコンテキスト**（https か localhost）でしか使えません。
  スマホから `http://192.168.x.x:5199` で開くと安全なコンテキストではないため、ローカルモードの予定 ID が作れませんでした。
  ローカルモードの ID は、同じ暗号用乱数（`crypto.getRandomValues`）で作るように直しました（`src/utils/id.ts`）。
  共有リンクのトークンはサーバーが作るので関係ありません。
- 同じ理由で、http の LAN アドレスでは「コピー」ボタン（クリップボード）が動きません。URL の欄をタップすると全体が選択されるので、
  手でコピーしてください。本番（https）では動きます。

## 手順 A: 予定の作成・保存・再編集・メモ・スワイプ（ローカルモード）

PC（PowerShell）で:

```powershell
# PC の LAN の IP アドレスを確認（例: 192.168.0.103）
Get-NetIPAddress -AddressFamily IPv4 | Where-Object { $_.IPAddress -like '192.168.*' } | Select-Object IPAddress
# LAN に公開して起動（テスト中だけ）
npx vite --mode mock --host 0.0.0.0 --port 5199 --strictPort
```

初めての場合、Windows が「ネットワークへのアクセスを許可しますか」と尋ねることがあります。**プライベートネットワーク（自宅）だけ**を許可してください。

Android Chrome で `http://<PC の IP>:5199` を開きます。予定はその Android の中（localStorage）に保存されます。

終わったら PC で **Ctrl+C** を押してサーバーを止めます。

## 手順 B: 共有画面と共有リンクの作成（モック API を Vite 経由で中継）

PC で2つのターミナルを使います:

```powershell
# ターミナル 1: モック API（127.0.0.1 だけで待ち受け。LAN には公開されない）
npm run shots:api
# ターミナル 2: アプリ（LAN に公開。/__mock_supabase をモック API へ中継）
npx vite --mode mockapi-lan
```

Android Chrome で:

1. `http://<PC の IP>:5199/__mock_supabase/__mock/signin` を開く（架空のユーザーでログインし、カレンダーに戻ります）
2. 右上の「共有」から共有画面を開く

終わったら、Android Chrome で `http://<PC の IP>:5199/__mock_supabase/__mock/signout` を開いて架空のログインを消し、
**両方のターミナルで Ctrl+C** を押してください。

### このモードで何がスマホに渡るか（再監査済み）

- 使う設定は **`.env.mockapi` だけ**です。ほかのファイルと混ぜず、PC のシェルの `VITE_*` 環境変数にも上書きされません。
  `.env.mockapi` が無い・キーが空・URL が loopback（`localhost` / `127.0.0.1`）でない場合は**起動しません**。
- `.env` / `.env.local` は**比較のためだけに**読みます。モックの値がそれらと同じなら取り違えとみなして**起動しません**。値は表示もしません。
- スマホに渡る設定は2つだけです: Supabase の接続先（＝開いているページ自身の `/__mock_supabase`）と、`.env.mockapi` の架空のキー。
  ほかの `VITE_*` は、ファイルからもシェルからも一切渡りません。
- LAN からモック API に届くのは、アプリが使う `/auth/v1/…`・`/rest/v1/…` と、ログイン・ログアウトの2ページだけです。
  モックの状態を変えるテスト用の `/__scenario` などは 404 になります。モック API 自体は 127.0.0.1 でしか待ち受けません。
- このモードではビルドできません（`vite build --mode mockapi-lan` はエラーで止まります）。

### テストが終わったら

- 架空のログインは、上のログアウトページで消えます（アプリの「ログアウト」でも消えます）。
- 手順 A で作った予定や、残った設定をまとめて消すには、Android Chrome の「サイトの設定」→ `http://<PC の IP>:5199` →「データを削除」。
- 架空のセッションは本物の Supabase では使えません（別のキー名・別の宛先）。残っていても本番には影響しませんが、消しておくと次のテストが確実です。

## 実機での確認項目（この順に）

| # | 手順 | 確認すること | モード |
| --- | --- | --- | --- |
| 1 | 一覧で「この日に予定を追加」→ タイトルを入れる | シートが画面いっぱいに開く。上の「保存」「キャンセル」が見える | A |
| 2 | 「保存」 | エラーが出ず、一覧に予定が出る（以前は `crypto.randomUUID is not a function`） | A |
| 3 | 保存した予定をタップして開き直す → 時刻を変えて保存 | 変更が反映される。もう一度開いても同じ | A |
| 4 | メモ欄をタップして2行入力（Enter で改行） | キーボードが出ても、メモ欄と上の「保存」「キャンセル」が見える。フォームを上下にスクロールできる | A |
| 5 | メモの下の「完了」をタップ | キーボードが閉じ、メモの内容は残る。シートは閉じない | A |
| 6 | Android の「戻る」 | ブラウザの通常の戻る動作（アプリが戻る操作を横取りしない） | A |
| 7 | 一覧で左へスワイプ → 右へスワイプ | 翌日 → 元の日。上の日付の帯も一緒に動く。縦スクロールでは日付が変わらない | A |
| 8 | 予定の上から横にスワイプ | 日付が変わり、予定は開かない。そのあとすぐ予定をタップすると開く | A |
| 9 | 「月」で左右にスワイプ。31日を選んでから翌月へ | 翌月・前月。1月31日の翌月は2月（3月に飛ばない） | A |
| 10 | 手順 B でログイン → 「共有」 | 共有画面が全画面で開く | B |
| 11 | 「リンクを作成」 | URL が表示される（コピーは手で） | B |

確認できなかった項目・違う動きをした項目は、画面写真（個人情報が写らないもの）と一緒に記録してください。

## ほかの方式（使う前に承認が必要）

| 方式 | 内容 | 必要な操作 |
| --- | --- | --- |
| USB ＋ `adb reverse` | USB でつなぎ、スマホの `localhost:5199` / `localhost:54321` を PC へ転送。スマホからは localhost（安全なコンテキスト）に見え、LAN に何も公開しない。既存の `shots:app` がそのまま使える | スマホの開発者向けオプションと USB デバッグを有効にし、PC に adb（Android Platform Tools）を入れる |
| HTTPS（ローカル CA） | ローカル CA で LAN の IP 用の証明書を作り、開発サーバーを https で起動 | 証明書の作成と、**スマホへの CA 証明書のインストール（信頼設定）**。証明書・秘密鍵はリポジトリに入れない |
| Chrome のフラグ | Android Chrome の `chrome://flags/#unsafely-treat-insecure-origin-as-secure` に `http://<PC の IP>:5199` を登録 | スマホの Chrome の設定変更（テスト後に戻す） |
